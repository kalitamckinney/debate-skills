# Accessibility Checklist

Use this checklist before publishing or updating any page on the course site.

## 1. Alternative text for every image

- [ ] Every informative image has alt text that describes its **content and purpose**, not just what it is.
  - Weak: "Photo of students"
  - Strong: "Two students at podiums facing each other during a formal debate round"
- [ ] Charts, diagrams, and infographics have alt text that states the key takeaway. Put longer descriptions in the text near the image.
- [ ] Purely decorative images are marked decorative (in Google Sites, leave the alt text empty; in HTML, use `alt=""`).
- [ ] Images that contain text repeat that text in the alt text or on the page.

## 2. High-contrast colors

- [ ] Body text has a contrast ratio of at least **4.5:1** against its background (WCAG 2.2 AA).
- [ ] Large text (18pt+, or 14pt+ bold) and meaningful icons have at least **3:1**.
- [ ] Text placed over images or banners stays readable. Add a solid overlay behind the text if needed.
- [ ] Color is never the only way information is shown. For example, "correct" and "incorrect" also use a label or an icon.
- [ ] Check colors with a contrast checker such as [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/).

## 3. Captions and transcripts for video and audio

- [ ] Every video has **accurate captions**. Review and correct auto-generated captions (names and debate terms are often wrong).
- [ ] Every audio file (podcast, recorded speech) has a **text transcript** linked next to it.
- [ ] Videos where important information is only visual (e.g., a speaker's gestures, slides) have that information described in the narration or the transcript.
- [ ] Media never autoplays.

## 4. Context-independent link text

- [ ] Link text makes sense **on its own**, because screen reader users often navigate by a list of links.
  - Weak: "Click here", "Read more", "This link"
  - Strong: "Download the debate rubric (PDF)", "Watch the sample rebuttal speech (4 min)"
- [ ] Links to files name the file type (PDF, DOCX, etc.).
- [ ] Links that open in a new tab say so.
- [ ] Raw URLs are not used as link text.

## 5. Headings that show the page structure

- [ ] Each page has one **Title / Heading 1** that names the page.
- [ ] Sections use **Heading 2**, sub-sections use **Heading 3**, with no skipped levels (no jumping from H2 to H4).
- [ ] Headings are real heading styles, not text made bold or larger.
- [ ] Heading text describes what is in the section (e.g., "Step 2: Build your argument", not "Part 2").

## Quick test before publishing

1. Tab through the page with the keyboard only. Can you reach and use every link and button?
2. Read only the headings. Do they outline the page?
3. Read only the links. Does each one make sense?
4. Turn the sound off and play each video. Is everything still understandable?
